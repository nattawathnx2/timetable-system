# Timetable System

ระบบจัดตารางเรียน พัฒนาด้วย Node.js, Express และ PostgreSQL โดยให้บริการหน้าเว็บจากโฟลเดอร์ `public` และใช้ session สำหรับการเข้าสู่ระบบ

## วัตถุประสงค์และขอบเขตของระบบ

Timetable System เป็นระบบจัดการตารางเรียนที่พัฒนาขึ้นสำหรับใช้งานภายในสถานศึกษา โดยมีวัตถุประสงค์เพื่อช่วยจัดการข้อมูลที่เกี่ยวข้องกับการจัดตารางเรียน เช่น อาจารย์ รายวิชา ห้องเรียน กลุ่มนักศึกษา และตารางเรียน ให้สามารถจัดการได้ผ่านระบบเดียว

ระบบออกแบบให้มีการกำหนดสิทธิ์การเข้าถึงตามบทบาทของผู้ใช้งาน โดยมีผู้ดูแลระบบ (Admin) เป็นผู้จัดการข้อมูลและสร้างบัญชีผู้ใช้งานสำหรับเข้าใช้ระบบ อาจารย์และนักศึกษาสามารถเข้าสู่ระบบด้วยบัญชีที่ได้รับจากผู้ดูแลระบบ โดยระบบไม่มีฟังก์ชันสมัครสมาชิกด้วยตนเอง (Self-registration)

ระบบนี้มีวัตถุประสงค์เพื่อใช้งานภายในสถานศึกษา ไม่ได้ออกแบบมาเป็นแพลตฟอร์มสมัครสมาชิกสาธารณะ

## ความสามารถหลัก

- เข้าสู่ระบบและจัดการการยืนยันตัวตน
- จัดการข้อมูลอาจารย์
- จัดการรายวิชา
- จัดการห้องเรียน
- จัดการกลุ่มนักศึกษา
- จัดการตารางเรียน
- จัดการผู้ใช้และตรวจสอบสิทธิ์ผู้ดูแลระบบ

> การเข้าถึงข้อมูลและหน้าจอจัดการขึ้นอยู่กับบทบาทและสิทธิ์ของผู้ใช้

## เทคโนโลยีที่ใช้

- Node.js
- Express
- PostgreSQL
- `pg` สำหรับเชื่อมต่อ PostgreSQL
- `express-session` สำหรับ session
- `bcrypt` สำหรับการแฮชรหัสผ่าน
- `dotenv` สำหรับโหลดค่าจากไฟล์ `.env`
- `nodemon` สำหรับพัฒนาระบบ

## สิ่งที่ต้องเตรียม

- ติดตั้ง Node.js และ npm
- ติดตั้งและเปิดใช้งาน PostgreSQL
- มีฐานข้อมูล PostgreSQL ที่เตรียมตารางให้ตรงกับที่ระบบใช้งาน

## การติดตั้ง

1. เปิด Terminal หรือ PowerShell ในโฟลเดอร์โปรเจกต์
2. ติดตั้ง dependencies:

   ```bash
   npm install
   ```

3. สร้างไฟล์ `.env` ที่ root ของโปรเจกต์ โดยใช้ตัวแปรตามตัวอย่างด้านล่าง
4. ตั้งค่า PostgreSQL ให้ตรงกับข้อมูลใน `.env` และเตรียม schema ของฐานข้อมูลให้เรียบร้อย
5. เริ่มระบบตามหัวข้อถัดไป

## การตั้งค่า Environment Variables

สร้างไฟล์ `.env` ในโฟลเดอร์หลักของโปรเจกต์:

```dotenv
DB_USER=your_postgres_username
DB_HOST=localhost
DB_NAME=your_database_name
DB_PASSWORD=your_postgres_password
DB_PORT=5432
SESSION_SECRET=replace_with_a_long_random_secret
```

เปลี่ยนค่าตัวอย่างให้ตรงกับเครื่องของคุณ ห้ามนำค่าจริงใน `.env` ไปเผยแพร่หรือ commit ลง Git

## การเริ่มระบบ

รันเซิร์ฟเวอร์:

```bash
npm start
```

สำหรับโหมดพัฒนา ซึ่งจะรีสตาร์ตเซิร์ฟเวอร์เมื่อมีการเปลี่ยนแปลงไฟล์:

```bash
npm run dev
```

เซิร์ฟเวอร์กำหนดให้ทำงานที่พอร์ต `3000` เมื่อเริ่มสำเร็จ ให้เปิดเบราว์เซอร์ไปที่:

`http://localhost:3000`

## โครงสร้างโปรเจกต์

```text
timetable-system/
├── database/                 # โฟลเดอร์สำหรับไฟล์ฐานข้อมูล (ปัจจุบันไม่มีไฟล์)
├── public/                   # ไฟล์หน้าเว็บ HTML, CSS และ JavaScript ฝั่ง client
├── src/
│   ├── db/
│   │   └── connection.js     # การเชื่อมต่อ PostgreSQL ผ่าน pg Pool
│   ├── middleware/
│   │   └── auth.js           # Middleware สำหรับตรวจสอบการยืนยันตัวตน/สิทธิ์
│   ├── routes/
│   │   ├── auth.js           # Routes สำหรับการยืนยันตัวตน
│   │   ├── rooms.js          # Routes สำหรับห้องเรียน
│   │   ├── schedules.js      # Routes สำหรับตารางเรียน
│   │   ├── student-groups.js # Routes สำหรับกลุ่มนักศึกษา
│   │   ├── subjects.js       # Routes สำหรับรายวิชา
│   │   ├── teachers.js       # Routes สำหรับอาจารย์
│   │   └── users.js          # Routes สำหรับผู้ใช้
│   └── server.js             # จุดเริ่มต้น Express server
├── .env                      # ค่าตั้งค่าส่วนตัว (ไม่ควร commit)
├── .gitignore
├── package.json
└── package-lock.json
```

## API Routes หลัก

| Prefix | หน้าที่ |
|---|---|
| `/auth` | การเข้าสู่ระบบและการยืนยันตัวตน |
| `/teachers` | ข้อมูลอาจารย์ |
| `/subjects` | ข้อมูลรายวิชา |
| `/rooms` | ข้อมูลห้องเรียน |
| `/student-groups` | ข้อมูลกลุ่มนักศึกษา |
| `/schedules` | ข้อมูลตารางเรียน |
| `/users` | ข้อมูลผู้ใช้และการตรวจสอบสิทธิ์ |

ตัวอย่าง endpoint สำหรับตรวจสอบสิทธิ์ผู้ดูแลระบบ:

- `GET /users/auth/admin-check`

Endpoint นี้ต้องใช้ session ที่ผ่านการยืนยันตัวตน และตรวจสิทธิ์ผู้ดูแลระบบก่อนอนุญาตให้เข้าถึง

## ความปลอดภัย

- ไฟล์ `.env` และโฟลเดอร์ `node_modules/` ถูกระบุไว้ใน `.gitignore`
- อย่าแชร์ `SESSION_SECRET` หรือรหัสผ่านฐานข้อมูล
- การซ่อนเมนูในหน้าเว็บไม่ใช่กลไกควบคุมสิทธิ์เพียงอย่างเดียว ฝั่ง server ต้องตรวจสิทธิ์ก่อนส่งข้อมูลหรือดำเนินการที่จำกัดสิทธิ์

## ฐานข้อมูล

โปรเจกต์ใช้ PostgreSQL โดยอ่านค่าการเชื่อมต่อจากตัวแปร `DB_USER`, `DB_HOST`, `DB_NAME`, `DB_PASSWORD` และ `DB_PORT` ในไฟล์ `.env`

ใน repository ปัจจุบันยังไม่มีไฟล์ SQL สำหรับสร้างฐานข้อมูลหรือตาราง ดังนั้นต้องเตรียมฐานข้อมูลและ schema ที่ระบบต้องใช้แยกต่างหากก่อนเริ่มใช้งาน
